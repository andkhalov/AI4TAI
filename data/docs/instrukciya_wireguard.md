# Инструкция: подключение к корпоративной сети через WireGuard

Документ учебный. ИТ-департамент, версия 1.4 от 02.06.2026.

## 1. Назначение

WireGuard используется для доступа сотрудников к внутренним ресурсам:
серверу 1С (msk-app20), файловому серверу, RDP-шлюзу и GraphDB.
Доступ выдаётся по заявке руководителя в службу поддержки.

## 2. Установка клиента (Windows)

1. Скачать установщик с https://www.wireguard.com/install/ (только с
   официального сайта).
2. Установить от имени администратора.
3. Получить файл конфигурации `<фамилия>.conf` от ИТ-департамента через
   корпоративную почту. Файл содержит приватный ключ, пересылать его
   третьим лицам запрещено.
4. В приложении WireGuard: «Добавить туннель» → «Импорт из файла».
5. Нажать «Подключить». Статус «Активен», в поле «Последнее рукопожатие»
   появляется время.

## 3. Параметры конфигурации

```
[Interface]
PrivateKey = <выдаётся ИТ>
Address = 10.8.0.X/32
DNS = 10.8.0.1

[Peer]
PublicKey = <ключ сервера>
Endpoint = vpn.example-technoavia.ru:51820
AllowedIPs = 10.8.0.0/24, 192.168.1.0/24
PersistentKeepalive = 25
```

Подсеть 192.168.1.0/24 — серверный сегмент (1С, файлы, RDP-шлюз).
Подсеть 10.8.0.0/24 — адреса VPN-клиентов.

## 4. Типовые проблемы

### 4.1. Нет рукопожатия (handshake)

Признак: поле «Последнее рукопожатие» пустое, счётчик «Получено» равен 0.

Причины и действия:
- Расхождение системного времени клиента более чем на 90 секунд.
  Проверить синхронизацию времени: `w32tm /resync`.
- Порт UDP 51820 заблокирован провайдером или гостевой сетью.
  Попробовать мобильную сеть.
- Приватный ключ клиента не соответствует публичному ключу на сервере
  (конфигурация от другого сотрудника или устаревшая). Запросить новый
  файл конфигурации.

### 4.2. Рукопожатие есть, ресурсы недоступны

- Проверить `AllowedIPs`: если указана только подсеть 10.8.0.0/24,
  серверный сегмент 192.168.1.0/24 маршрутизироваться не будет.
- Проверить DNS: `nslookup msk-app20 10.8.0.1`.
- Проверить, что в другом VPN-клиенте (например, корпоративный VPN
  заказчика) не включён режим «весь трафик через туннель».

### 4.3. Соединение обрывается каждые несколько минут

- Отсутствует `PersistentKeepalive = 25` за NAT.
- Один и тот же файл конфигурации используется на двух устройствах
  одновременно. Сервер принимает последнее рукопожатие; устройства
  вытесняют друг друга. На каждое устройство нужен свой ключ.

## 5. Отзыв доступа

Доступ отзывается при увольнении, смене должности и по заявке службы
безопасности. Ключ удаляется на сервере в тот же день. Повторное
подключение возможно только по новой заявке.

## 6. Логи

Клиент WireGuard для Windows пишет журнал в окне «Журнал» приложения.
Для обращения в поддержку приложить последние 100 строк журнала и
скриншот вкладки туннеля.
